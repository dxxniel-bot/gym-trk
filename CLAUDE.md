## What it is
A mobile-first web app (works on iPhone via "Add to Home Screen") to log gym workouts + nutrition. Rebuilt from the user's old Expo Go app (`ironLOG`). Aesthetic: **terminal/CLI, monochrome, JetBrains Mono**.

## Architecture
- **`index.html`** — the ENTIRE app (HTML + CSS + JS inline). Single-page, JS-rendered screens via a `render()` router on `state.screen`. ~all logic here.
- **`manifest.json` + `sw.js`** — PWA (installable + offline). `sw.js` is **network-first** for same-origin (online = latest deploy, offline = cache) — cache name bump (`gymtrk-vN`) forces refresh.
- **`*-prototype.html`** — static design references (superseded by `index.html`; keep for design history).

- **No-data-loss rule:** keep the LS key stable, never clear it, migrate additively in `migrate()`. Editing code never touches LS. `[settings]` has export/import JSON (backup) + "log in" restores from a pasted backup.
- **Identity/variant engine (v206–v210, 2026-07-25):** exercise edits are per split-DAY instance, never global by name — `saveExEdit` merges into (never replaces) the exercise at `db.split.days[di].exercises[ei]`; editing "chest press" on day A never touches a same-named exercise on day B, and the mid-session editor no longer mirrors into the split at all (opt-in `ee_tosplit` checkbox, off by default). `variantKey(e)` = `canonType(type)+uni+assisted+weighted` — same name, different variant (machine vs. free, bilateral vs. unilateral, assisted vs. weighted) is a fully independent history/prefill/%. Prefill (formerly "v68", now baseline-driven) and progress % both resolve against the **equivalent antecedent** via `baselineSetsFor()` — an occurrence-aware ladder (exact `exId` → same day+name+variant+ordinal occurrence → unique day+name+variant → unique name+variant nearby) — NEVER "any past occurrence of the same name," so a fresh top set is never compared against a fatigued dropset/extra from the tail of a prior session. `alignSetIdx()` then pairs today's sets to the baseline's like-for-like (drop/non-drop, side, ordinal) instead of a positional clamp, so an unmatched extra set shows no badge instead of a false one. `%`/progress badges use `sessionFatigueContext()`+`correctedE1RM()` (fresh-equivalent, discounting intra-session fatigue from primary AND weighted secondary muscles) with confidence tiers (`progConfidence`) so a weak match shows `~` and a wide mismatch shows direction only, never a fabricated number. Muscle-volume attribution (`musclesOf()`) resolves **at read time** from the split via `exId`, never mutating saved sessions — "lo que hiciste es inmutable; cómo se clasifica se resuelve en vivo": add triceps as a secondary to an existing exercise and every past session under that `exId` counts toward triceps in //VOLUME retroactively, with zero rewritten data. Drop sets are subseries of their parent working set (array stays flat, `isDrop` flag as before — the 4 existing 0.5-weightings are untouched), inserted via `dropInsertIdx()` immediately after their parent + any drops it already has (never appended to the end), numbered `1, 1.5, 2, 3` via `setLabels()` (chains to `.6`/`.7`); `emptySet()`'s clone-template no longer leaks `isDrop` onto a plain `[+ set]` add. Bodyweight exercises show `[BW <live kg>] [+lastre]`: `latestBodyweight()`/`effW()` always recompute from the most recent `db.bodyweight` entry (never a frozen per-set snapshot, including for past sessions), `bwMissing()` surfaces "BW sin peso" instead of silently scoring against 0. History editing (`state.screen='histedit'`, `state._histSessId`) reuses the exact live-session row components (`renderSetRow`'s new `actPrefix` param dispatches to isolated `h_*` handlers — `h_setf`/`h_done`/`h_fs`/`h_addset`/`h_dropset`/`h_delset` — that only ever touch the targeted past `db.sessions[]` entry, never `db.activeWork`) in a denser `.hist-compact` layout; it exposes full per-set correction but deliberately NOT structural edits (rename/machine-change/add-remove-exercise — those stay split/live-session decisions) and shows only an exercise-level badge, not per-set ▲▼. Permanent self-checks (`_identitySelfCheck`/`_dropsetSelfCheck`/`_baselineSelfCheck`/`_variantSelfCheck`/`_historyEditSelfCheck`) run on `?selftest=1`.

### Built-in base foods (`BASE_FOODS`)
A curated, code-embedded table (~259 entries) of generic **whole/basic foods** OpenFoodFacts lacks (huevo, res, cebolla, tortilla, frijol, aguacate, pechuga, arroz, café…). Mexican-staple + protein-leaning, broad coverage (dairy, poultry, beef/pork, fish/seafood, legumes, grains, veg, fruit, nuts/seeds, fats, sugars/condiments, snacks, supplements, beverages, prepared dishes). Each is already in canonical shape (`per100` for all MACROKEYS, `base:'g'|'ml'`, `sizes` with natural piece/serving). Built via a terse `add(name,kcal,p,c,f,opt)` helper (`opt`: `s`ugar `fi`ber `na`+`k` mg `caf` `sv`/`pc`/`ct` grams `sl` label `base` `en`=English alias). Values are ~per-100 g edible-portion USDA approximations (composite dishes are rougher). **Bilingual search** (user reported better MFP hits in English): every entry has an `en` alias and `bfNorm()` (accent-insensitive, lowercased) matches **name OR alt** — so "chicken"→Pechuga de pollo, "onion"→Cebolla. **Surfaced in search, not copied to LS:** matched in `openFoodAdd`'s inline `#fa_q` list (under a BÁSICOS group) and in `openNameSearch` (BÁSICOS above OFF PRODUCTOS). Pick → `data-act="pickbase"` → `openLog(food,{isNew:true})`; "guardar + loguear" copies it into `db.foods` (keeps its `bf_*` id, then shows under RECIENTES and is filtered out of BÁSICOS to avoid dupes). To extend: add more `add(...)` rows with an `en:` alias.

The big `BASE_FOODS` IIFE is hard to edit by exact-match; to regenerate it, write the new block to a temp file and splice with Node: `h.replace(/const BASE_FOODS=\(function\(\)\{[\s\S]*?\n\}\)\(\);/, newBlock)` (verify exactly one match first).

### External (client-side, no keys/backend)
- **OpenFoodFacts** — barcode lookup (`/api/v2/product/{code}.json`) + name search (`/cgi/search.pl`). Barcode-not-found → offers **photo-of-label OCR** (primary) and name search (both link the food to the scanned code in `foods[]`).
- **Live barcode scanner** (`openBarcode()` → `startScan()`) — MFP-style: tap scan → camera opens immediately with center reticle overlay → auto-detects → found→`openVerify` (forward), not-found→`openRegisterMenu(code)` (register, barcode linked). **Architecture = live preview + background still-frame decode** (the key fix — Quagga LiveStream and `BarcodeDetector` both fail on iOS Safari): we own the `<video>` via `getUserMedia` (`facingMode:environment` 1280×720), then a loop every ~360 ms grabs the current frame to an offscreen canvas (center band, ~62% height, downscaled ≤1000 px) and decodes it **as a still image** — `BarcodeDetector.detect(canvas)` if available (Android/desktop, faster ~170 ms), else `Quagga.decodeSingle({src:canvas.toDataURL()})` (reliable on iOS). A `decoding` mutex serializes decodes so the loop and the manual button never run Quagga concurrently. **On hit:** `navigator.vibrate(55)` + green lock-on animation (`.scan-reticle.hit` → green frame `bcpop` + `✓` `bcchk`, scan line hidden) so the user can lower the phone, ~430 ms pause, then `doLookup`. **📷 capturar** button = thorough full-res decode of the *current preview frame* via `decodeImgSrc()` (multi-patch `decodeSingle`), or a file photo (`decodeBarcodeImage`) if no live camera — no longer ignored, since there's no running LiveStream to collide with. Manual numeric entry is the last fallback. `window._scanner={stream,video,timer}`; `stopScan()`/`closeModal()` clear the timer + stop tracks so the camera light goes off on close. **Replaced html5-qrcode (v5 ZXing → v6 Quagga2 LiveStream → v47 still-frame decode)** because live detection never worked reliably on iPhone.
- **Tesseract.js** (CDN, lazy) — photo→OCR of nutrition labels (FALLBACK when AI proxy off). `prepImage()` preps image; `parseNutritionText()` handles kcal-vs-kJ, comma decimals, g↔mg.
- **AI label reading (Gemini via Cloudflare Worker)** — `proxy/gymtrk-ai-worker.js` holds the OWNER's one Gemini key (free tier) so users need no key. App: `AI_PROXY_URL` const (empty ⇒ falls back to OCR), `aiPhoto()` POSTs a compressed JPEG dataURL → proxy → structured nutrition → verify; `labelPhoto()` routes to AI if configured else OCR; `fileToDataURL/sanitizePer/labelFallback`. To enable: deploy the Worker (see `proxy/README.md`), set `AI_PROXY_URL`. Verified via mocked proxy in preview. **NOTE: the AI schema returns the OLD per-serving shape and will be upgraded together with the canonical food-model refactor (below).**
